# Blue Mage Set Builder

A Dalamud plugin for FFXIV: reads the player's learned Blue Mage spells and builds the
best 24-spell active set for the content they pick, then applies it.

**Published** 2026-10-14 as `joshua88wa/FFXIV-Dalamud-BlueMageSetBuilder`, v0.1.0.0,

## Build

```
cd BlueMageSetBuilder
dotnet build -c Release
```

Produces `BlueMageSetBuilder/bin/Release/BlueMageSetBuilder/latest.zip`. Keep the name
`latest.zip`; the repo.json download links depend on it.

For local testing, add `BlueMageSetBuilder/bin/Release/BlueMageSetBuilder.dll` under
Dalamud Settings -> Experimental -> Dev Plugin Locations.

15 (`Dalamud.NET.Sdk/15.0.0`), in the `.csproj` SDK version and the plugin `.json`.

## How the plugin is put together

- `Spellbook` is the only class that touches game memory. It builds the spell list from
  the `AozAction` / `AozActionTransient` / `Action` sheets, answers "is it learned" via
  `UIState.IsUnlockLinkUnlocked(Action.UnlockLink)`, and reads and writes the 24 slots
  through `ActionManager.BlueMageActions` / `SetBlueMageActions`.
- `SetBuilder` is pure logic: profile + learned predicate + exclusions in, chosen spells
  and "worth learning" list out. `Layout` places them in slots, keeping already-active
  spells where they are.
- `Blockers` is every reason a change cannot happen: conditions (combat, casting,
  zoning, cutscenes) and buffs from spells. Working rule from testing: a spell cannot
  move or leave while it is recasting or while its buff is on you (confirmed for
  Aetheric Mimicry and Mighty Guard). No hand-made list: `Spellbook` gives each spell
  `GrantedStatuses` (Action.StatusGainSelf, plus statuses named after the spell, plus a
  verified floor for 11417 and 18322) and `EndsOnReuse` ("ends upon reuse" in the
  description, plus the same floor, since the text check is English only). Only
  self-applied statuses count, so a boss's "Doom" is ignored.
- `SetApplier.BlockingStatusesFor` checks buffs of spells whose slot changes. Up front
  it only blocks on buffs it can end (Recast or ClickOff); wait-only ones (Basic
  Instinct is permanent while solo) count only after a refusal. A refusal while any
  active spell's buff is up adds that spell to `strictSpells` for the session, so the
  next press offers to end it even if the spell is not moving. The game has no data
  for any of this; `CanAssignBlueMageAction` is known only by address, so not called.
- `SetApplier` is shared by the window and `/blusets apply`. Ending buffs runs as a
  per-frame sequence: wait for casts, end one buff (recast via `UseAction` after
  `GetActionStatus`, or `ExecuteStatusOff` then `/statusoff`), wait out the GCD, next
  buff, then cooldowns, then apply. Each step has a 6 second timeout. It reads the
  slots back after writing, because the return value alone does not prove the change
  took.
- `ProfileStore` loads `Profiles.json`: the embedded copy by default, or a user copy in
  the plugin config folder, which replaces it entirely.

## The icon and the screenshots

`images/icon.png` is generated by `tools/make-icon.ps1` (System.Drawing, no editable
source). Change the numbers in the script and re-run it rather than editing the PNG.
It must stay square and at most 512x512, or Dalamud rejects it and only logs an error.

The three images are not interchangeable:

| File | Used by | Limit |
|---|---|---|
| `images/screenshot.jpg` (or `.png`) | the README | none |
| `images/preview.png` | `ImageUrls`, so the in-game installer | **730x380 maximum** |
| `images/icon.png` | `IconUrl`, so the installer | **512x512 maximum, square** |

To replace the screenshot: copy a new one to the clipboard, run
`tools/save-clipboard-image.ps1`, then `tools/make-preview.ps1` to regenerate
`images/preview.png` scaled to fit. `make-preview.ps1` uses whichever of
`screenshot.png` / `screenshot.jpg` is newest; if the extension changes, update the
`<img>` in the README to match.

`IconUrl` and `ImageUrls` point at `main` on GitHub, so nothing shows in the installer
until those files are pushed. They are fetched live; replacing one needs no release.

## Creature sources (Sources.json)

The game only records where a spell is learned (`AozActionTransient.Location`: a zone
or a duty), never which creature. `Sources.json` fills that in from the FFXIV Online
Wiki's Blue Magic Spellbook page. It is generated, never hand-edited:
`tools/make-sources.ps1` downloads the page source and keeps only plain facts per
source (Creature, Note for boss position, Place, Level, Coords). Re-run it after a
patch adds spells, then rebuild; it is an embedded resource.

Joshua chose to embed facts with credit rather than fetch at runtime (2026-10-10).
The wiki declares no licence, so keep it to facts, keep the credit in the README and
the tooltip, and do not copy prose.

`SpellSources.MatchGameSource` picks the source at the game's own location for the
table column: normalised containment first, then ignoring brackets per listed place
(primals are "(Extreme)" in game, "(Hard)" on the wiki), then totems. 120 of 123
located spells match; 59, 74 and 75 show the game location only because the wiki
does not list it. Boss position exists for only about a quarter of duty sources;
Joshua chose to show it where known rather than research the rest.

## The Masked Carnivale (issue #1, in progress)

Menu: profiles have a `Group` (heading in the Content menu) and an optional `Stage`.
Stage profiles are not listed in the Content menu; choosing "The Masked Carnivale"
shows a Stage picker instead (`MainWindow.DrawStagePicker`, `Configuration.SelectedStage`,
`SelectedProfile == "carnivale"`). `/blusets apply stage N` applies one.

Game data (`CarnivaleStages`), all language-independent:
- Stages: ContentFinderCondition rows with ContentType 27; stage number is
  `Content.RowId - 35000` (35001 = stage 1 ... 35032 = stage 32).
- Enemies: AOZContent row N (Order == row id == stage) has Act1-3 and Act1-3FightType.
  **FightType 1 = AOZArrangement subrows (enemy group); 2 and 3 = AOZBoss row, whose
  Boss is the enemy.** Reading every act as a group gives the wrong enemies for boss
  stages. Checked: 3 Zipacna, 25 Azulmagia, 30 Siegfried, 32 Goldor.
- AOZContentBriefingBNpc has vulnerability flags (slow, petrify, paralysis, interrupt,
  blind, stun, sleep, bind, heavy, instant death), shown under the picker. Its
  element/damage-type columns are small numbers whose meaning is not worked out yet.

Spell lists per stage, researched 2026-10-14:
- **Blue Academy** (mage.blue, source github.com/RoarkGit/Blue-Academy, updated for
  7.5, pushed Oct 2026): `content/masked-carnivale/stages/NN.md` has "Required Spells"
  and "Recommended Spells" sections using `{{< spell snake_case_name >}}`, so it parses
  reliably. 24 of 32 stages list spells; 1, 8, 10, 13, 15, 17, 18, 21 list none (easy
  stages). **No licence file.** Not yet imported; waiting on Joshua's decision.
- Icy Veins Carnivale guide: same shape, last updated 6.45 (2023), commercial copyright.
- FFXIV Online Wiki stage pages: strategy prose; spell mentions mix in the enemy's own
  moves, so not usable for automatic extraction.

## Spell numbers

Profiles use the Blue Magic Spellbook number (`AozActionTransient.Number`), not the
`AozAction` row id. They match from 50 upward but not below, so always use the number
the game shows.
